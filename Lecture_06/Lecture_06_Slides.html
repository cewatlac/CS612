Block A · 00:10–01:00

Designing the state

The DAG view · what the state must remember · a correctness template

DP is a path problem on a DAG of states

  • Nodes = states (subproblems).
  • Edges = transitions (a decision, with a cost/value).
  • Sources/sinks = base cases / the goal.
  • Optimal value = the best path; counting = the number of paths.
  • Evaluation order = any topological order of the DAG.
  • Cost = #states × transition cost = \(O(V+E)\) of the DAG.
A cyclic dependency means it is not DP (as stated): either the state is missing information, or the problem is a genuine shortest path with cycles (L10).

What must the state remember?

Principle: the state must contain exactly the information about the past that the remaining decisions and their costs depend on. The rest of the history must be irrelevant (a "Markov" property).

Example. Climb \(n\) stairs with steps of 1 or 2, never two 2-steps in a row. Count the ways.

  • State "\(i\) stairs done"? Not enough: whether a 2-step is allowed next depends on the last step.
  • State \((i,\ell)\), with \(\ell\in\{1,2\}\) the last step: \(W(i,1)=W(i-1,1)+W(i-1,2)\), \(W(i,2)=W(i-2,1)\).
Test for a candidate stateTake two different histories that lead to the same state. Must every continuation have the same value (cost, feasibility) for both? If not, the state is missing information.
And the opposite errorRemembering too much (e.g. the full set of items chosen) makes the state space exponential. Good design removes everything the future does not need.

A correctness template for DP

  1. State semantics: in words, what \(D[\text{state}]\) equals (e.g. "the length of an LCS of \(X[1..i]\) and \(Y[1..j]\)").
  2. Recurrence by case analysis on the last decision of an optimal solution.
  3. Correctness:
    1. Soundness: every value the recurrence produces is achievable (each case builds a valid solution);
    2. Optimality: an optimal solution falls into one of the cases, and its remainder is optimal for the smaller state (cut-and-paste).
  4. Base cases that match the semantics.
  5. Order: a topological order of the dependencies (or memoization).
  6. Answer extraction from the final state(s).
  7. Complexity: #states × cost per transition; space and how to reduce it.
  8. Reconstruction of an optimal solution (store choices, or re-derive them).

Three deep case studies

LCS · edit distance · matrix-chain multiplication

LCS: state, recurrence, and the key lemma

State: \(L[i][j]\) = the length of a longest common subsequence of \(X[1..i]\) and \(Y[1..j]\).

\[L[i][j]=\begin{cases}0 & i=0\text{ or }j=0\\ L[i-1][j-1]+1 & x_i=y_j\\ \max\big(L[i-1][j],\,L[i][j-1]\big) & x_i\ne y_j\end{cases}\]
Lemma (the match case is safe)If \(x_i=y_j\), some LCS of \(X[1..i],Y[1..j]\) uses \(x_i\) matched with \(y_j\).
Proof (exchange)Take any LCS \(Z\) and let its last matched pair be \((x_{i'},y_{j'})\), with \(i'\le i\), \(j'\le j\). If \(i'<i\) and \(j'<j\), appending the pair \((x_i,y_j)\) gives a longer common subsequence: a contradiction. Otherwise replace the last pair by \((x_i,y_j)\): still increasing, same length. So some LCS ends with \(x_i\) matched to \(y_j\), and by cut-and-paste its remainder is an LCS of \(X[1..i-1],Y[1..j-1]\).

Edit distance

State: \(E[i][j]\) = the minimum cost of transforming \(X[1..i]\) into \(Y[1..j]\), with insertion, deletion and substitution costing 1 each (a match costs 0).

\[E[i][j]=\min\begin{cases}E[i-1][j]+1 & \text{delete }x_i\\ E[i][j-1]+1 & \text{insert }y_j\\ E[i-1][j-1]+[x_i\ne y_j] & \text{match/substitute}\end{cases}\]

Base cases: \(E[i][0]=i\), \(E[0][j]=j\).

Correctness: write an optimal edit sequence as an alignment. Its last column is \((x_i,-)\), \((-,y_j)\) or \((x_i,y_j)\). These are exactly the three cases, and the rest of the alignment is optimal for the smaller state (cut-and-paste).

DAG viewA shortest path from \((0,0)\) to \((n,m)\) in a grid graph with edge weights 0/1. That makes it a special shortest-path problem, and this structure is what Myers' \(O((n+m)D)\) algorithm exploits.
General costs: any non-negative costs \(c_{ins}(y)\), \(c_{del}(x)\), \(c_{sub}(x,y)\) work unchanged (sequence alignment in bioinformatics). Affine gap penalties need extra state: "am I inside a gap?" (Gotoh).

Matrix-chain multiplication: interval states

\(A_1A_2\cdots A_n\), with \(A_i\) of size \(p_{i-1}\times p_i\). Multiplying \(p\times q\) by \(q\times r\) costs \(pqr\). Choose the parenthesisation that minimises the total cost.

State: \(M[i][j]\) = the minimum cost to compute \(A_i\cdots A_j\).

\[M[i][j]=\min_{i\le k<j}\Big(M[i][k]+M[k+1][j]+p_{i-1}p_kp_j\Big),\quad M[i][i]=0.\]

Last decision: the final multiplication splits the chain at some \(k\).

Order: by increasing chain length \(j-i\).

StatesTransitionTimeSpace
\(\Theta(n^2)\)\(O(n)\)\(\Theta(n^3)\)\(\Theta(n^2)\)
AskDimensions \(10\times100,\ 100\times5,\ 5\times50\). Compare \((A_1A_2)A_3\) with \(A_1(A_2A_3)\).
Greedy "multiply the cheapest adjacent pair first" is not optimal (exercise). The number of parenthesisations is a Catalan number: \(\Omega(4^n/n^{3/2})\).

MSc point"Conditional lower bounds" (fine-grained complexity) explain why decades of effort have not produced strongly subquadratic edit-distance algorithms. It is the polynomial-time analogue of NP-hardness (L13).

Synthesis

  1. DP = paths in a DAG of states: order = topological order; cost = #states × transition cost.
  2. The state must remember exactly what the future depends on. Apply the two-histories test.
  3. Correctness = state semantics + case analysis on the last decision + cut-and-paste + base cases.
  4. LCS/edit distance: prefix-pair states, \(\Theta(nm)\); linear space for values, Hirschberg for alignments. MCM: interval states, \(\Theta(n^3)\).
  5. "There is a DP" does not mean "this is the best algorithm": fine-grained lower bounds, and better special-case algorithms.
