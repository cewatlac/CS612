Divide-and-Conquer, Recurrences & Selection

Sorting needs \(\Omega(n\log n)\). Does finding the median? And how do we read a recursive algorithm's cost off its structure?

Where we are

L01 established

  • A complexity claim = model + input size + cost measure + guarantee type + bound
  • Correctness = spec + invariant/induction + termination
  • Comparison sorting needs \(\lceil\log_2 n!\rceil\) comparisons; adversary and decision-tree arguments
Today's question Finding the \(k\)-th smallest of \(n\) keys: can we beat sorting's \(\Theta(n\log n)\)? If yes, what kind of guarantee do we get: expected or worst case?

To answer it, we need tools to analyse recursive algorithms whose recursion is unbalanced.

Motivating problem: percentiles at scale

A monitoring system keeps \(n = 10^9\) request latencies in memory. Every minute it reports the median, the p99 and the p99.9.

  • Sorting: \(\approx n\log_2 n \approx 3\times10^{10}\) comparisons per report.
  • Is there a lower bound that makes this unavoidable?
  • The p99 of \(10^9\) values is the \(9.9\times10^8\)-th smallest. A heap of the top 1% has \(10^7\) entries. Is that better?

Floors and ceilings (\(T(\lceil n/2\rceil)\) etc.) almost never change the \(\Theta\) bound. The Akra–Bazzi theorem justifies ignoring them for a broad class of recurrences.

Substitution: guess, then prove by induction

Example. \(T(n)=2T(\lfloor n/2\rfloor)+1\). Guess \(T(n)=O(n)\).

Naive attempt: assume \(T(m)\le cm\) for \(m<n\):

\[T(n)\le 2c\lfloor n/2\rfloor+1\le cn+1.\]

\(cn+1\not\le cn\). The induction fails, even though the guess is right.

Fix: strengthen the hypothesis. Assume \(T(m)\le cm-d\):

\[T(n)\le 2\big(c\lfloor n/2\rfloor-d\big)+1\le cn-2d+1\le cn-d\]

whenever \(d\ge1\). Base case: choose \(c\) large relative to \(T(1)\).

RuleThe inductive step must prove exactly the hypothesis, with the same constants. "\(cn+1=O(n)\)" is not a valid step.

Recursion trees: where does the cost live?

\(T(n)=aT(n/b)+f(n)\): level \(j\) has \(a^j\) nodes of size \(n/b^j\), for total cost \(a^j f(n/b^j)\). Depth \(\log_b n\), with \(a^{\log_b n}=n^{\log_b a}\) leaves.

\[T(n)=\sum_{j=0}^{\log_b n-1}a^j f\!\left(\tfrac{n}{b^j}\right)+\Theta\!\left(n^{\log_b a}\right)\]

The per-level costs form (roughly) a geometric series. Three regimes:

  • decreasing down the tree → the root dominates → \(\Theta(f(n))\)
  • constant → \(\Theta(f(n)\log n)\)
  • increasing → the leaves dominate → \(\Theta(n^{\log_b a})\)

The Master theorem, precisely

Theorem (CLRS 4e, Thm 4.1) Let \(a\ge1\), \(b>1\), \(f\) asymptotically positive, and \(T(n)=aT(n/b)+f(n)\). Let \(w=\log_b a\) (the watershed exponent).
  1. If \(f(n)=O(n^{w-\varepsilon})\) for some \(\varepsilon>0\): \(T(n)=\Theta(n^{w})\).
  2. If \(f(n)=\Theta(n^{w}\log^k n)\) for some \(k\ge0\): \(T(n)=\Theta(n^{w}\log^{k+1}n)\).
  3. If \(f(n)=\Omega(n^{w+\varepsilon})\) for some \(\varepsilon>0\) and \(af(n/b)\le c f(n)\) for some \(c<1\) and all large \(n\) (regularity): \(T(n)=\Theta(f(n))\).
The "basic" textbook version has only \(k=0\) in case 2. The \(\log^k\) extension covers \(2T(n/2)+n\log n=\Theta(n\log^2 n)\).
Cases 1 and 3 need a polynomial gap \(n^{\varepsilon}\). A log-factor gap is not enough.

Case studies: when D&C wins, and when it doesn't

Maximum subarray · Strassen · selection in linear time

Maximum subarray: D&C, then do better

D&C: \(\Theta(n\log n)\)

The best subarray lies entirely in the left half, entirely in the right half, or crosses the midpoint. The crossing case = the best suffix of the left half + the best prefix of the right half: \(\Theta(n)\).

\(T(n)=2T(n/2)+\Theta(n)=\Theta(n\log n)\).

But: Kadane's scan, \(\Theta(n)\)

KADANE(A)
  best = A[1] ; cur = A[1]
  for i = 2 to n
      cur = max(A[i], cur + A[i])
      best = max(best, cur)
  return best
Invariant (after step i) \(cur\) = the maximum sum of a subarray ending at \(i\); \(best\) = the maximum sum of any subarray within \(A[1..i]\).
Lesson D&C gave a correct \(n\log n\) algorithm, but a stronger invariant (a DP state, as in L06) gives \(n\). The recurrence tells you what an algorithm costs; it does not tell you whether a better algorithm exists.

Strassen: trading multiplications for additions

Split \(n\times n\) matrices into \(2\times2\) blocks of size \(n/2\). The standard method needs 8 block products → \(T=8T(n/2)+\Theta(n^2)=\Theta(n^3)\).

Strassen (1969): 7 block products \(P_1..P_7\) plus 18 block additions/subtractions:

\[T(n)=7T(n/2)+\Theta(n^2)\;\Rightarrow\;\Theta(n^{\log_2 7})=\Theta(n^{2.807\ldots})\]

Case 1 of the Master theorem: \(n^2=O(n^{2.807-\varepsilon})\).

Theory vs. practice
  • Crossover with tuned \(\Theta(n^3)\) BLAS: typically \(n\) in the hundreds to low thousands (it depends on the machine).
  • Weaker numerical stability (subtractions amplify floating-point error).
  • Extra memory for temporaries.
  • The best known exponent today is \(\omega<2.372\) (2024), but those algorithms are "galactic".

Selection: specification and a first algorithm

SELECT\((A,k)\): given \(n\) distinct keys and \(1\le k\le n\), return the key of rank \(k\) (the \(k\)-th smallest).

RAND-SELECT(A, k)
  if |A| == 1 return A[1]
  p = uniformly random element of A
  L = {x ∈ A : x < p} ; R = {x ∈ A : x > p}
  if k ≤ |L|      return RAND-SELECT(L, k)
  if k == |L| + 1 return p
  return RAND-SELECT(R, k − |L| − 1)
Correctness by strong induction on \(|A|\): \(p\) has rank \(|L|+1\), and the rank of the answer within \(L\) or \(R\) is adjusted accordingly.
Expected \(O(n)\), intuition With probability \(\ge 1/2\) the pivot's rank lies in the middle half, and then the recursion keeps at most \(3n/4\) elements. On average, 2 partitions are needed to shrink by \(3/4\): \[E[T(n)]\le E[T(3n/4)]+2cn\;\Rightarrow\;O(n).\] Full indicator-variable analysis: L03.
Worst case: \(\Theta(n^2)\) (the pivot is always an extreme).

Median of medians (Blum, Floyd, Pratt, Rivest, Tarjan 1973)

SELECT(A, k)                       ▷ deterministic, n = |A|
  if n ≤ 140  sort A and return A[k]
  split A into ⌈n/5⌉ groups of ≤ 5 elements
  M = the median of each group         ▷ O(n): ≤ 6 comparisons per group
  x = SELECT(M, ⌈|M|/2⌉)              ▷ recursive: median of medians
  partition A around x into L, {x}, R
  if k ≤ |L|      return SELECT(L, k)
  if k == |L| + 1 return x
  return SELECT(R, k − |L| − 1)
Two recursive calls one on the \(\lceil n/5\rceil\) medians (to find a good pivot), one on the side that contains the answer (to use the pivot).

Key question: how large can \(L\) or \(R\) be?

The key lemma: the pivot is at least 30% in

Arrange the groups as columns, each sorted with its largest element at the top, and order the columns left to right by increasing median. The pivot \(x\) is the median of the middle row.

Lemma. At least \(\frac{3n}{10}-6\) elements are \(>x\), and likewise \(<x\).

Proof. At least half of the \(\lceil n/5\rceil\) groups have a median \(\ge x\). Each such group, except possibly \(x\)'s own group and a final partial group, contributes 3 elements \(\ge x\) (its median and the two below it). So there are at least \(3\big(\tfrac12\lceil\tfrac n5\rceil-2\big)\ge\frac{3n}{10}-6\) such elements. Hence \(|L|,|R|\le\frac{7n}{10}+6\).

Linear time: the substitution proof

\(T(n)\le T(\lceil n/5\rceil)+T(\tfrac{7n}{10}+6)+an\) for \(n>140\), with \(T(n)=O(1)\) for \(n\le140\).

Claim: \(T(n)\le cn\) for a suitable \(c\) Assume it holds for all smaller arguments. Then \[T(n)\le c\left(\tfrac n5+1\right)+c\left(\tfrac{7n}{10}+6\right)+an=\tfrac{9}{10}cn+7c+an.\] This is \(\le cn\) iff \(c\left(\tfrac{n}{10}-7\right)\ge an\). For \(n\ge140\), \(\tfrac n{10}-7\ge\tfrac n{20}\), so \(c\ge20a\) suffices (and also choose \(c\) large enough for the base cases).
Why it works\(\frac15+\frac7{10}=\frac9{10}<1\): the total work shrinks geometrically, level by level.
The price\(c\ge20a\): a large constant. In our experiment, about 8.4n comparisons vs. 3.4n for random pivots.

Why group size 5? (And why not 3?)

For odd group size \(g\), about half the groups contribute \(\frac{g+1}{2}\) elements on each side of \(x\):

\[\text{discarded}\ \gtrsim\ \frac{g+1}{4g}\,n,\qquad |L|,|R|\ \lesssim\ \frac{3g-1}{4g}\,n.\]

Sizes of the two recursive calls: \(\frac{n}{g}+\frac{3g-1}{4g}n=\frac{3g+3}{4g}\,n<n\iff g>3\).

3\(T(n/3)+T(2n/3)+O(n)\)\(\Theta(n\log n)\)
5\(T(n/5)+T(7n/10)+O(n)\)\(\Theta(n)\)

Synthesis

  1. Write the recurrence from the algorithm: number of subproblems, their sizes, non-recursive work.
  2. Recursion tree to guess; substitution to prove, with the exact hypothesis (strengthen if needed).
  3. Master theorem: compare \(f(n)\) with \(n^{\log_b a}\); needs a polynomial gap (cases 1/3) plus regularity (case 3). Know the gaps and the unequal-split cases.
  4. Selection is \(\Theta(n)\), strictly easier than sorting: expected via random pivots, worst case via median of medians (\(\frac15+\frac7{10}<1\)).
  5. Choosing a method depends on the guarantee type, the constants, the adversary, the memory, and the number of queries.
