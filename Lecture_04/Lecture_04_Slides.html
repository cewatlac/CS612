Hashing & Randomized Data Structures

"\(O(1)\) expected" and "\(O(\log n)\) expected": expected over what, and what happens when someone chooses your keys?

Saturday 17 October 2026 · 3 hours
Due today: PS1 · Project M1 (team + topic)

Where we are

L03 gave us

  • Expected time \(=\max_x\mathbb E_r[T(x,r)]\): worst-case input, our coins
  • Guarantees hold against an oblivious adversary
  • Indicators + linearity; Markov; amplification
Today Apply the same idea to data structures: choose the hash function (or the tower heights) at random, so that no fixed set of keys is bad. Then compare with deterministic worst-case structures.

Motivating incident: hash flooding (2011)

At the 28C3 conference (Dec 2011), Klink and Wälde showed that many web platforms (PHP, Java, Python, Ruby, ASP.NET…) stored HTTP POST parameters in hash tables with a fixed, public hash function.

  • An attacker sends one request with \(n\) parameter names that all collide.
  • Each insert scans the whole chain: \(\Theta(n^2)\) total.
  • A ~2 MB request could keep a CPU core busy for tens of seconds or more.

Fixes shipped: randomized (seeded) hash functions, and limits on the number of parameters.

Block A · 00:10–01:00

Universal hashing

From "assume random keys" to "choose a random function"

Every fixed hash function has a bad input

Universe \(U\) of keys, table size \(m\), fixed \(h:U\to\{0,\dots,m-1\}\).

PigeonholeSome slot receives at least \(|U|/m\) keys. If \(|U|\ge nm\), there are \(n\) keys that all hash to the same slot.

For \(h(k)=k\bmod 2^{16}\): all multiples of \(2^{16}\) (aligned addresses, IDs with low bits zero, timestamps rounded to seconds…).

Universal families

Definition (Carter & Wegman 1979)A family \(\mathcal H\) of functions \(U\to\{0,\dots,m-1\}\) is universal if for all \(x\ne y\in U\): \[\Pr_{h\in\mathcal H}\big[h(x)=h(y)\big]\le\frac1m .\] (Probability over a uniformly random choice of \(h\); the keys are fixed.)
TheoremChaining, \(h\) drawn from a universal family, any fixed set \(S\) of \(n\) keys, load factor \(\alpha=n/m\). For any key \(x\), the expected number of keys of \(S\setminus\{x\}\) in \(x\)'s chain is \(\le\alpha\). So a search costs expected \(O(1+\alpha)\).
ProofLet \(C_y=\mathbb 1[h(y)=h(x)]\). The chain length is \(\sum_{y\in S\setminus\{x\}}C_y\), and by linearity \(\mathbb E=\sum_y\Pr[h(y)=h(x)]\le\frac{n}{m}\).

A universal family and why it works

Pick a prime \(p>\) every key. For \(a\in\{1,\dots,p-1\}\), \(b\in\{0,\dots,p-1\}\):

\[h_{a,b}(k)=\big((ak+b)\bmod p\big)\bmod m .\]

Proof idea. Fix \(x\ne y\). Let \(r=(ax+b)\bmod p\) and \(s=(ay+b)\bmod p\).

  1. \(r\ne s\), since \(r-s\equiv a(x-y)\not\equiv0\) (\(p\) is prime).
  2. The map \((a,b)\mapsto(r,s)\) is a bijection onto pairs with \(r\ne s\): solve \(a=(r-s)(x-y)^{-1}\), \(b=r-ax\).
  3. So \((r,s)\) is uniform over the \(p(p-1)\) pairs with \(r\ne s\). For each \(r\), at most \(\lceil p/m\rceil-1\le\frac{p-1}{m}\) values \(s\ne r\) have \(s\equiv r\pmod m\).

Hence \(\Pr[\text{collision}]\le\frac{p(p-1)/m}{p(p-1)}=\frac1m\).

In practice: multiply-shift \(m=2^\ell\), \(w\)-bit keys, random odd \(a\): \[h_a(k)=\big(a\cdot k\bmod 2^w\big)\gg(w-\ell).\] One multiplication and one shift. \(\Pr[\text{collision}]\le\frac2m\) (Dietzfelbinger et al. 1997): "universal up to a factor 2". It is used in today's experiment.
Integer division by a prime is slow, which is why fast hash tables use multiply-shift or tabulation hashing. Strings need polynomial hashing (L11).

Open addressing: more independence needed

  • R4: unsuccessful search in open addressing costs \(\le\frac1{1-\alpha}\) expected probes under uniform hashing, an idealised assumption (every probe sequence is a random permutation).
  • For linear probing with a real hash family, pairwise universality is not enough: some 2-universal families give \(\Theta(\log n)\) expected probes.
  • 5-independent families give expected \(O(1)\) (Pagh, Pagh, Ružić 2007); simple tabulation hashing also works (Pătraşcu & Thorup 2012).
Take-away "Expected \(O(1)\)" depends on which randomness assumption: fully random, \(k\)-independent, universal. Chaining needs only universal hashing. Linear probing needs more. The worst case is \(\Theta(n)\) for all of them.

Linear probing is often faster in practice (cache locality). The theory explains what it requires.

Perfect hashing and skip lists

Worst-case \(O(1)\) for static sets · randomized balancing for ordered sets

Perfect hashing (Fredman, Komlós, Szemerédi 1984)

Static set of \(n\) keys: build once, then only lookups.

  1. Level 1: hash into \(m=n\) buckets with a universal \(h\). Bucket \(j\) gets \(n_j\) keys. Retry while \(\sum_j n_j^2>4n\).
  2. Level 2: bucket \(j\) gets its own table of size \(n_j^2\) with its own universal \(h_j\). Retry until it has no collisions.

Lookup: two hash evaluations, one comparison: worst-case \(O(1)\).

Why FKS works: two expectations

Level 2: a table of size \(n_j^2\) is collision-free with probability \(\ge\frac12\) Expected colliding pairs \(=\binom{n_j}{2}\cdot\frac{1}{n_j^2}<\frac12\). By Markov, \(\Pr[\ge1\text{ collision}]<\frac12\). So the expected number of retries is \(<2\) (geometric).
Level 1: total space \(\mathbb E\big[\sum_j n_j^2\big]<2n\) \(\sum_j n_j^2=\sum_j\big(n_j+2\binom{n_j}{2}\big)=n+2\cdot\#\{\text{colliding pairs}\}\), so \[\mathbb E\Big[\sum_j n_j^2\Big]\le n+2\binom n2\frac1n<2n.\] By Markov, \(\Pr\big[\sum n_j^2>4n\big]<\frac12\): expected \(<2\) level-1 attempts.
Result: expected \(O(n)\) construction time, \(O(n)\) space, worst-case \(O(1)\) lookup. Quadratic space per bucket is affordable because the buckets are small on average.

Skip lists (Pugh 1990): randomized balancing

  • Level 0: a sorted linked list of all \(n\) keys.
  • Each key is promoted to the next level with probability \(\frac12\), independently: level \(L\) with \(\Pr[L\ge h]=2^{-h}\).
  • Search: start at the top-left; move right while the next key is \(<x\); otherwise drop down a level.
  • Insert: search, flip coins for the height, splice into each level. Delete: unsplice. No rotations, no rebalancing.
  • Expected pointers: \(\sum_h n2^{-h}=2n\).

Skip-list analysis: expected \(O(\log n)\), not worst case

Height\(H=\max_x L_x\). Union bound: \(\Pr[H\ge h]\le n2^{-h}\). So \(\Pr[H\ge3\log_2n]\le n^{-2}\) and \(\mathbb E[H]\le\log_2n+1\).
Search cost (backward analysis)Walk the search path backwards from the target. At each node, the path came from above with probability \(\frac12\) (the node was promoted) or from the left with probability \(\frac12\). Expected steps to climb one level \(=2\). Climbing \(\le H\) levels gives expected cost \(\le2(\log_2 n+1)+O(1)\).
Worst case: \(\Theta(n)\)If the coins give every key level 0, a search walks the whole list. This happens with tiny probability, but not zero. The legacy slides' "average and worst-case \(O(\log n)\)" is wrong.

The guarantee is over our coin flips for any fixed operation sequence (oblivious adversary). An adversary who sees the heights (e.g. through timing) can choose which keys to query.

Synthesis

  1. Every fixed hash function has a bad key set (pigeonhole). "Expected \(O(1)\)" with a fixed \(h\) is an assumption about the keys.
  2. Universal hashing: \(\Pr_h[h(x)=h(y)]\le\frac1m\) ⇒ expected chain \(\le1+\alpha\) for every fixed key set. Keep the seed secret.
  3. Perfect hashing: static set, worst-case \(O(1)\) lookups, expected \(O(n)\) construction; \(\mathbb E\sum n_j^2<2n\).
  4. Skip lists: expected (and w.h.p.) \(O(\log n)\); worst case \(\Theta(n)\). Simple, ordered, concurrency-friendly.
  5. Measured constants and memory layout often dominate between structures with the same \(O(\cdot)\).
