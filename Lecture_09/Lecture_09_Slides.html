MST structure and algorithms

Cut and cycle properties · Kruskal · Prim · Borůvka

The cut property

\(G=(V,E)\) connected, undirected, weights \(w\). A cut \((S,V\setminus S)\) is crossed by an edge with one endpoint on each side. It respects an edge set \(A\) if no edge of \(A\) crosses it.

Theorem (cut property, generic form)Let \(A\) be contained in some MST, let the cut \((S,V\setminus S)\) respect \(A\), and let \(e\) be a lightest edge crossing it. Then \(A\cup\{e\}\) is contained in some MST.
Proof (exchange)Let \(T\supseteq A\) be an MST. If \(e\in T\), done. Otherwise \(T+e\) contains a cycle through \(e=(u,v)\). The \(T\)-path from \(u\) to \(v\) crosses the cut at some edge \(e'\). \(e'\notin A\), since the cut respects \(A\). And \(w(e)\le w(e')\), since \(e\) is a lightest crossing edge. \(T'=T+e-e'\) is a spanning tree with \(w(T')\le w(T)\), so it is an MST containing \(A\cup\{e\}\).

The cycle property and the blue/red framework

Cycle propertyIf \(e\) is the unique heaviest edge on some cycle of \(G\), then \(e\) belongs to no MST. (Proof: an exchange argument, part of PS3.)

Tarjan's two rules (colour the edges; uncoloured = undecided):

  • Blue rule: pick a cut with no blue edge crossing it; colour a lightest uncoloured crossing edge blue.
  • Red rule: pick a cycle with no red edge; colour a heaviest uncoloured edge on it red.

Theorem: applying the rules in any order until all edges are coloured leaves the blue edges forming an MST.

Kruskal and Prim: implementation decides cost

Kruskal

sort edges by weight
for each edge (u,v) in order
    if FIND(u) ≠ FIND(v):  add (u,v); UNION(u,v)

Sort \(O(m\log m)=O(m\log n)\) + DSU \(O(m\,\alpha(n))\). If the edges arrive pre-sorted (or are small integers: radix sort): nearly linear.

Prim

grow a tree T from any start vertex
repeat n − 1 times: add the lightest edge leaving T
Prim's priority queueTime
unsorted array (adjacency matrix)\(\Theta(n^2)\)
binary heap, lazy (push on each relaxation)\(O(m\log n)\)
binary heap with decrease-key\(O(m\log n)\)
Fibonacci heap\(O(m+n\log n)\) (amortized)
Legacy correctionThe old slides quoted "\(O(E+V\log V)\) with a priority queue (heap)" for a lazy binary-heap implementation. That code is \(O(E\log V)\). \(O(E+V\log V)\) requires a Fibonacci heap. Always name the priority queue.

Borůvka (1926): all components at once

F = n singleton components
while F has more than one component
    for each component C
        find the lightest edge leaving C
    add all these edges to F   ▷ merge components
  • Each phase at least halves the number of components, so there are \(\le\log_2 n\) phases.
  • Each phase is \(O(m)\), so the total is \(O(m\log n)\).
  • Naturally parallel and distributed: components act independently.
Tie-breaking is essentialWith equal weights, components may pick edges that form a cycle: in a triangle of weight-1 edges, each vertex may pick a different edge. Break ties consistently (e.g. by edge index) to make the weights effectively distinct.
TheoryBorůvka phases + contraction are the basis of the randomized expected linear-time MST algorithm (Karger, Klein, Tarjan 1995). The best deterministic bound is \(O(m\,\alpha(m,n))\) (Chazelle 2000).

Block B · 01:10–02:00

Disjoint-set union

Linking rules · path compression · \(O(m\,\alpha(n))\) amortized

The DSU abstract data type

Maintain a partition of \(\{1..n\}\) under

  • FIND(x): the representative of \(x\)'s set;
  • UNION(x,y): merge the two sets.

Forest representation: each set is a rooted tree, the root is the representative, and FIND follows parent pointers.

Naive linking (root of \(x\) under root of \(y\), always): \(n-1\) unions can build a path, and each FIND on its bottom costs \(\Theta(n)\).

Uses
  • Kruskal's cycle test
  • Connectivity under edge insertions (online)
  • Unification in type inference and compilers
  • Image segmentation / connected components of pixels
  • The scheduling matroid of L08: the "latest free slot"
  • Offline LCA (Tarjan)

Not supported: splitting a set (deletions). Dynamic connectivity with deletions is much harder.

Union by size: logarithmic depth

Rule: link the root of the smaller tree (fewer nodes) under the root of the larger.

LemmaWith union by size (and no path compression), every node has depth \(\le\log_2 n\). So FIND is \(O(\log n)\) worst case.
ProofA node's depth increases (by exactly 1) only when its tree is linked under another root. That happens only if its tree was the smaller one, so the size of the tree containing the node at least doubles. Sizes never exceed \(n\), so this happens at most \(\log_2 n\) times.
Union by rank

Store an upper bound on the height (rank) instead of the size, and link the lower rank under the higher; increment on ties. Same \(O(\log n)\) guarantee. The rank analysis is PS3 Q3.

Why ranks? They stay meaningful under path compression (heights do not), and they are the quantity used in the \(\alpha(n)\) analysis.

Path compression

FIND(x)
  if parent(x) ≠ x
      parent(x) = FIND(parent(x))
  return parent(x)

After a FIND, every node on the path points directly to the root.

  • Compression alone (arbitrary linking): \(O(\log n)\) amortized per operation (Tarjan & van Leeuwen 1984). A single FIND can still cost \(\Theta(n)\).
  • An iterative two-pass version avoids recursion depth; path halving and path splitting are one-pass alternatives with the same bounds.
Legacy correctionThe old slides stated "path compression: \(O(\log n)\) in the worst case". Path compression gives an amortized bound. One operation can be linear.

Both heuristics: \(O(m\,\alpha(n))\) amortized

Theorem (Tarjan 1975; Tarjan & van Leeuwen 1984)With union by rank (or size) and path compression, any sequence of \(m\) operations on \(n\) elements takes \(O(m\,\alpha(n))\) time, where \(\alpha\) is the inverse Ackermann function. This is tight: \(\Omega(m\,\alpha(n))\) holds for any pointer-based DSU (Tarjan 1979) and in the cell-probe model (Fredman & Saks 1989).

Ackermann-type function: \(A_0(j)=j+1\), and \(A_k(j)=A_{k-1}^{(j+1)}(j)\) (iterate \(j+1\) times).

\(A_1(1)=3,\ A_2(1)=7,\ A_3(1)=2047,\ A_4(1)\gg10^{80}\).

\(\alpha(n)=\min\{k: A_k(1)\ge n\}\), so \(\alpha(n)\le4\) for every \(n\) that could ever occur.

Read the theorem carefully
  • It is amortized: a total over the sequence, not a bound on each operation. A single FIND can still take \(\Theta(\log n)\).
  • "\(\alpha(n)\le4\) in practice" is a statement about \(\alpha\), not about the constant hidden in \(O(\cdot)\).
  • Legacy slides: "\(\alpha(n)\) … reaching 4*n at most" is meaningless. Correct: \(\alpha(n)\le4\).

A simpler bound: \(O(m\log^* n)\) (proof sketch)

\(\log^*n\) = the number of times \(\log_2\) must be applied to reach \(\le1\). (\(\log^*2^{65536}=5\).)

Facts about ranks (with union by rank + compression): ranks only increase along a path to the root; a node of rank \(r\) has had \(\ge2^r\) descendants, so at most \(n/2^r\) nodes ever have rank \(r\). (The first fact is a warm-up; the second is the PS3 lemma.)

  1. Rank groups: group \(g\) holds ranks in \((t_{g-1},t_g]\), with \(t_0=1,\ t_g=2^{t_{g-1}}\) (towers of 2). There are \(\le\log^*n+1\) groups.
  2. Charge each step of a FIND from node \(x\) to its parent:
    • to the FIND, if the parent is in a different group or is the root: \(\le\log^*n+2\) such steps per FIND;
    • otherwise to the node \(x\). After compression \(x\)'s parent has a strictly higher rank, so \(x\) is charged at most \(t_g\) times while in group \(g\).
  3. Nodes in group \(g\): \(\le\sum_{r>t_{g-1}}n/2^r\le n/2^{t_{g-1}}=n/t_g\). Total node charges per group \(\le n\), so \(\le n(\log^*n+1)\) overall.

Total: \(O\big((m+n)\log^*n\big)\) amortized.

Groups · 12 min

Synthesis

  1. Cut property (safe edges) and cycle property (unsafe edges): every MST algorithm applies them in some order.
  2. Kruskal: sort + DSU. Prim: the priority queue decides: array \(n^2\), binary heap \(m\log n\), Fibonacci heap \(m+n\log n\). Borůvka: parallel phases, needs consistent tie-breaking.
  3. Choose by density, by the representation (are edges stored or computed?), and by the environment (distributed? pre-sorted?).
  4. DSU: size/rank ⇒ \(O(\log n)\) worst case; + compression ⇒ \(O(m\,\alpha(n))\) amortized, and tight.
  5. Random workloads do not reveal worst-case behaviour. Construct adversaries to test guarantees.
