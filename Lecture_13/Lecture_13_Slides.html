P, NP and reductions

Certificates · direction · what a proof requires

Decision problems, P and NP

  • A decision problem = a set of yes-instances (encoded as strings). Optimisation problems have decision versions: "is there a colouring with \(\le k\) colours?"
  • P: decidable in time polynomial in the input length.
  • NP: yes-instances have certificates of polynomial length that a polynomial-time verifier accepts. No-instances have none.
\[x\in L\iff\exists y,\ |y|\le p(|x|):\ V(x,y)=1\]

\(\mathrm P\subseteq\mathrm{NP}\) (the verifier ignores \(y\)). Whether \(\mathrm P=\mathrm{NP}\) is open.

Polynomial-time reductions and their direction

Definition\(A\le_p B\) if there is a polynomial-time computable \(f\) with \(x\in A\iff f(x)\in B\) for every instance \(x\).

Meaning: "\(A\) is no harder than \(B\)". An efficient algorithm for \(B\) gives one for \(A\): compute \(f(x)\), then run \(B\)'s algorithm.

To show \(B\) is hard, reduce a known hard problem to \(B\): \(\text{(known hard)}\le_p B\).

Transitivity: \(A\le_p B\) and \(B\le_p C\) imply \(A\le_p C\).

The classic error"I reduced my problem \(B\) to SAT, so \(B\) is NP-hard." That shows only \(B\in\) NP (no harder than SAT). The arrow points the wrong way.
MnemonicThe reduction transforms instances of the known hard problem into instances of your problem. You build gadgets inside your problem.

NP-hard, NP-complete, and what a proof requires

  • NP-hard: every problem in NP reduces to it. It need not be in NP (e.g. optimisation versions, the halting problem).
  • NP-complete: NP-hard and in NP.
  • Cook–Levin (1971): SAT is NP-complete. Every NP verifier's computation can be encoded as a CNF formula.
  • Consequence: if any NP-complete problem is in P, then P = NP.
Recipe: proving \(X\) NP-complete
  1. \(X\in\mathrm{NP}\): describe a certificate and a polynomial verifier.
  2. Choose a known NP-complete \(Y\) with a similar structure.
  3. Construct \(f\): instances of \(Y\) → instances of \(X\). Argue it runs in polynomial time (output size!).
  4. (⇒) \(y\) yes ⇒ \(f(y)\) yes: map a solution forwards.
  5. (⇐) \(f(y)\) yes ⇒ \(y\) yes: map any solution of \(f(y)\) backwards. This is often the hard part.

Block B · 01:10–02:00

A chain of reductions

SAT → 3-SAT → Independent Set → Vertex Cover, Clique

SAT → 3-SAT

3-SAT: CNF where every clause has exactly 3 literals. In NP: the certificate is an assignment.

Reduction: transform each clause \(C=(\ell_1\lor\dots\lor\ell_k)\) separately:

  • \(k=1\): \((\ell_1\lor y\lor z)(\ell_1\lor y\lor\bar z)(\ell_1\lor\bar y\lor z)(\ell_1\lor\bar y\lor\bar z)\).
  • \(k=2\): \((\ell_1\lor\ell_2\lor y)(\ell_1\lor\ell_2\lor\bar y)\).
  • \(k=3\): unchanged.
  • \(k>3\): a chain with new variables \(y_1..y_{k-3}\): \[(\ell_1\lor\ell_2\lor y_1)(\bar y_1\lor\ell_3\lor y_2)\cdots(\bar y_{k-3}\lor\ell_{k-1}\lor\ell_k).\]
Correctness of the chain (\(k>3\))

(⇒) If some \(\ell_i\) is true, set \(y_j=\) true for \(j<i-1\) and false for \(j\ge i-1\). Every chain clause is then satisfied.

(⇐) If all \(\ell_i\) are false, the first clause forces \(y_1\), which forces \(y_2\), …, \(y_{k-3}\), and the last clause \((\bar y_{k-3}\lor\ell_{k-1}\lor\ell_k)\) is false. So some \(\ell_i\) must be true.

Size: \(O(k)\) new clauses per clause, so linear overall.

3-SAT → Independent Set

IS: does \(G\) have \(k\) pairwise non-adjacent vertices?

Construction from a 3-CNF \(\varphi\) with \(m\) clauses:

  • a triangle for each clause (one vertex per literal occurrence);
  • a conflict edge between every pair of complementary literals (\(x_i\) and \(\bar x_i\)) in different triangles;
  • \(k=m\).

Size: \(3m\) vertices, \(O(m^2)\) edges.

Proof(⇒) Pick one true literal per clause: \(m\) vertices, one per triangle, never complementary, so independent. (⇐) An independent set of size \(m\) has exactly one vertex per triangle (triangles are cliques). No complementary pair is chosen, so setting the chosen literals to true is a consistent assignment (other variables arbitrary), and it satisfies every clause.

IS ↔ Vertex Cover ↔ Clique

Complement lemma\(S\) is an independent set of \(G\) ⟺ \(V\setminus S\) is a vertex cover of \(G\).

Proof: \(S\) is independent ⟺ no edge has both endpoints in \(S\) ⟺ every edge has an endpoint in \(V\setminus S\).

So \((G,k)\in\) IS ⟺ \((G,n-k)\in\) VC, and both directions are reductions.

Clique lemma\(S\) is an independent set of \(G\) ⟺ \(S\) is a clique of \(\bar G\) (the complement graph).

So \((G,k)\in\) IS ⟺ \((\bar G,k)\in\) CLIQUE. Building \(\bar G\) costs \(O(n^2)\).

Chain: SAT \(\le_p\) 3-SAT \(\le_p\) IS \(\le_p\) VC, CLIQUE. All are NP-complete (each is in NP, via a subset certificate).

Easy special cases exist: VC in bipartite graphs is polynomial (König, L12); IS in trees and interval graphs is polynomial (DP, greedy). NP-completeness is about the general problem.

Weak vs. strong NP-hardness (the bridge from L07)

  • Subset sum, knapsack, partition: NP-complete, but solvable in pseudo-polynomial time \(O(nT)\). The hardness needs numbers exponential in \(n\): weakly NP-hard.
  • TSP, 3-partition, bin packing, graph colouring: NP-hard even when all numbers are bounded by a polynomial in \(n\): strongly NP-hard. No pseudo-polynomial algorithm unless P = NP.

Why it matters for design: for weakly hard problems with small numbers in practice, DP is a real solution; for strongly hard ones it is not.

Reading a hardness proof critically

Ask:

  1. Which problem was reduced to which?
  2. Do the constructed instances look like your instances (numbers, structure, size)?
  3. Does the hardness survive your special structure (planar? bounded degree? small \(k\)?)

Hardness of the general problem does not settle your special case.

Solving hard problems exactly

Backtracking · branch-and-bound · search trees · DP over subsets

Exhaustive search, done intelligently

Backtracking = DFS over partial solutions

SEARCH(partial)
  if partial is complete: record it; return
  for each extension e of partial
      if FEASIBLE(partial + e):   ▷ prune infeasible branches
          SEARCH(partial + e)
  • Subset sum with pruning ("stop when the running sum exceeds \(T\)") is valid only for non-negative numbers. The legacy code did not state this.
  • N-Queens: one queen per row, columns and diagonals as bit sets, which prunes \(n^n\) down to far fewer nodes. The time is still exponential, but the base of the exponent is much smaller.
Branch-and-bound (optimisation)At each node, compute an optimistic bound on any completion. If bound ≤ incumbent (for maximisation), prune.
Validity requirementThe bound must be \(\ge\) the value of every completion of the node (for maximisation). Then pruning never discards an optimum.
Legacy correctionThe old "B&B knapsack" code pruned only infeasible branches (\(W<0\)). That is backtracking with no bound, \(O(2^n)\).

Knapsack branch-and-bound with the fractional bound

Sort the items by value/weight. At a node (items \(1..i\) decided, weight \(w\), value \(v\)):

\[\text{bound}=v+\text{(greedy fractional knapsack on items }i{+}1..n\text{ with capacity }W-w).\]
Why it is validEvery 0/1 completion is a feasible solution of the fractional relaxation over the remaining items, and the greedy solves the fractional problem optimally (L08, exercise A1). So bound ≥ every completion's value.

Branch: take item \(i+1\) (if it fits) first, then skip it. Prune when bound ≤ incumbent.

What makes B&B fast or slow
  • A tight bound (close to the true optimum) prunes early.
  • A good incumbent early (e.g. start from the greedy solution).
  • A good branching order.

On strongly correlated instances (\(v_i\approx w_i+c\)), all items have similar density, the fractional bound is loose everywhere, and B&B degenerates.

Search trees with provable bounds: Vertex Cover

Question: is there a vertex cover of size \(\le k\)?

  • Edge branching: pick any edge \((u,v)\). Either \(u\) or \(v\) is in the cover. Branch on both with \(k-1\). The tree has \(\le2^k\) leaves: \(O(2^k\,m)\).
  • Degree branching: pick \(v\) of maximum degree \(d\). Either \(v\) is in the cover (\(k-1\)), or all of \(N(v)\) is (\(k-d\)). If \(d\ge2\): \(T(k)\le T(k-1)+T(k-2)\), so \(O(1.618^k)\). With \(d\ge3\): \(O(1.47^k)\). If every degree is \(\le2\), the graph is paths and cycles: solve directly.

These algorithms are exponential only in \(k\): they are fixed-parameter tractable.

Held–Karp (1962): DP over subsets for TSP\(C(S,j)\) = the cheapest path from city 1 that visits exactly \(S\) and ends at \(j\): \[C(S,j)=\min_{i\in S\setminus\{j\}}C(S\setminus\{j\},i)+d(i,j).\] \(O(n^22^n)\) time instead of \((n-1)!\): \(n=25\) is fine, \(n=60\) is not.
Meet-in-the-middle (knapsack/subset sum): \(O(2^{n/2}n)\). Inclusion–exclusion: colouring in \(O(2^nn)\) (Björklund–Husfeldt–Koivisto 2009).

Synthesis

  1. NP = efficiently verifiable. NP-complete = in NP and every NP problem reduces to it.
  2. To prove \(X\) hard: reduce a known hard problem to \(X\). Polynomial construction + (⇒) + (⇐) + membership.
  3. The chain SAT → 3-SAT → IS ↔ VC ↔ Clique: gadgets enforce "choose one" and "be consistent".
  4. Weakly vs. strongly NP-hard decides whether pseudo-polynomial DP is an option.
  5. Exact methods: pruning, valid bounds, and smart branching change what is solvable in practice, though not the worst case.
