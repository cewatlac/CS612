Two motivating problems

1 · The killer adversary

McIlroy (1999) wrote a short program that, while a library's quicksort runs, answers its comparisons so as to force \(\Theta(n^2)\) behaviour for essentially any deterministic pivot rule, including median-of-3.

Real systems have been attacked with crafted inputs (sorting, hashing).

Can any algorithm be safe against this?

2 · Trust but verify

A GPU service returns \(C\) and claims \(C=AB\) for \(n\times n\) matrices. Recomputing \(AB\) costs \(\Theta(n^3)\) (or \(n^{2.8}\)).

Can we check the claim in \(O(n^2)\) time, if we accept a tiny chance of being fooled?

Randomization is not "hoping the input is random". The algorithm flips the coins; the input can be the worst possible.

"Expected time" means something precise

\[T_{\text{exp}}(n)=\max_{|x|=n}\ \mathbb E_{r}\big[T(x,r)\big]\]
  • The max over inputs is outside: a worst-case input, chosen first.
  • The expectation over our coins is inside.
  • Contrast with average case: \(\mathbb E_{x\sim\mathcal D}[T(x)]\), which trusts a model of the inputs.

Adversary models

  • Oblivious: fixes the input (or operation sequence) before any coin flip. Our guarantees hold.
  • Adaptive: sees our random choices (or can predict them) and reacts. Expected-time guarantees can fail.
Where adaptive adversaries appear
  • A predictable random generator: fixed seed, time-based seed
  • An online data structure whose behaviour (timing!) leaks the random choices
  • Hash functions with a public seed: hash flooding (L04)

Engineering rule: seed from a good entropy source once, keep the seed secret where attackers exist, and log it for reproducibility.

Freivalds' algorithm (1977)

FREIVALDS(A, B, C, k)       ▷ n × n matrices
  repeat k times
      choose r ∈ {0,1}ⁿ uniformly at random
      if A·(B·r) ≠ C·r         ▷ three matrix–vector products
          return "C ≠ AB"       ▷ certainly correct
  return "C = AB"               ▷ possibly wrong

Cost: \(O(kn^2)\) instead of \(\Theta(n^3)\).

Theorem If \(C=AB\), the algorithm always accepts. If \(C\ne AB\), one trial rejects with probability \(\ge\frac12\), so the algorithm wrongly accepts with probability \(\le 2^{-k}\).

Monte Carlo with one-sided error.

Proof: the principle of deferred decisions

Proof Let \(D=AB-C\ne 0\), so some entry \(d_{ij}\ne0\). A trial accepts iff \(Dr=0\), which implies \((Dr)_i=0\): \[(Dr)_i=\sum_{\ell}d_{i\ell}r_\ell=d_{ij}r_j+y,\qquad y=\sum_{\ell\ne j}d_{i\ell}r_\ell .\] Condition on all coordinates except \(r_j\), which fixes \(y\). Then \((Dr)_i=0\) iff \(r_j=-y/d_{ij}\). At most one of the two values \(r_j\in\{0,1\}\) satisfies this, so \[\Pr[Dr=0]\le\Pr[(Dr)_i=0]\le\tfrac12 .\] The \(k\) trials are independent, so \(\Pr[\text{all accept}]\le2^{-k}\).
TechniqueDeferred decisions: fix all random choices except one, then show that the bad event constrains that last choice.

Amplification: how many repetitions?

One-sided error \(p\)

Repeat \(k\) times, and accept only if all runs accept: error \(\le p^k\).

For \(\delta\): \(k=\lceil\log(1/\delta)/\log(1/p)\rceil\). Freivalds: \(\delta=10^{-9}\) needs \(k=30\).

Two-sided error \(\le\frac12-\varepsilon\)

Repeat \(k\) times and take the majority. Chernoff–Hoeffding:

\[\Pr[\text{majority wrong}]\le e^{-2\varepsilon^2k}.\]

So \(k=O(\varepsilon^{-2}\log(1/\delta))\).

Cost of certaintyEach factor of 10 in confidence costs a constant number of extra trials: \(\log_2 10\approx3.3\) for Freivalds.
Independence is essentialRe-running with the same random bits (e.g. re-seeding with the same time value) gives the same error again, and amplification does nothing.

Analysing randomized quicksort and quickselect

Indicators · linearity of expectation · exact constants · concentration

Randomized quicksort: what to count

RQS(A, lo, hi)
  if lo < hi
      p = uniform random index in [lo, hi]
      swap A[p], A[hi]
      q = PARTITION(A, lo, hi)   ▷ Lomuto
      RQS(A, lo, q − 1)
      RQS(A, q + 1, hi)

Let the keys in sorted order be \(z_1<z_2<\dots<z_n\) (distinct).

  • Running time \(=\Theta(n+X)\), where \(X\) = the total number of key comparisons.
  • Every comparison is between the current pivot and another element of its subarray.
  • So each pair \(z_i,z_j\) is compared at most once: after partitioning, the pivot is never used again.
\[X=\sum_{i<j}X_{ij},\qquad X_{ij}=\mathbb 1[z_i\text{ and }z_j\text{ are compared}]\]

The key lemma

Lemma\(\Pr[z_i\text{ and }z_j\text{ are compared}]=\dfrac{2}{j-i+1}\) for \(i<j\).
Proof Let \(Z_{ij}=\{z_i,z_{i+1},\dots,z_j\}\), so \(|Z_{ij}|=j-i+1\). Until some element of \(Z_{ij}\) becomes a pivot, all of \(Z_{ij}\) stay in the same subarray, because any pivot outside \(Z_{ij}\) is smaller or larger than all of them. Consider the first pivot chosen from \(Z_{ij}\):
  • If it is \(z_i\) or \(z_j\): the two are compared (the pivot meets every element of its subarray).
  • If it is some \(z_\ell\) with \(i<\ell<j\): \(z_i\) and \(z_j\) are separated forever and never compared.
Each element of \(Z_{ij}\) is equally likely to be that first pivot (pivots are uniform within the current subarray, which contains all of \(Z_{ij}\)). So the probability is \(2/(j-i+1)\).

Summing: \(\mathbb E[X]\approx1.39\,n\log_2 n\)

\[\mathbb E[X]=\sum_{i=1}^{n-1}\sum_{j=i+1}^{n}\frac{2}{j-i+1}=\sum_{i=1}^{n-1}\sum_{d=2}^{n-i+1}\frac{2}{d}\;<\;2n\,H_n=2n\ln n+O(n).\]

Exact value: \(\mathbb E[X]=2(n+1)H_n-4n\). Since \(2\ln n=(2\ln 2)\log_2 n\approx1.386\log_2 n\):

comparisons
Lower bound \(\lceil\log_2 n!\rceil\) (L01)\(n\log_2 n-1.44n\)
Merge sort (worst case)\(\approx n\log_2 n-n\)
Randomized quicksort (expected)\(\approx1.39\,n\log_2 n-2.85n\)
Quicksort makes about 39% more comparisons than optimal in expectation. It usually wins anyway: it is in place, has sequential access and a tight inner loop.

Beyond expectation: concentration

An expectation alone does not rule out frequent slow runs. For quicksort, much more is true:

Fact (high probability)For any constant \(c\), there is a \(c'\) such that randomized quicksort makes at most \(c'n\ln n\) comparisons with probability \(\ge1-n^{-c}\).

Sketch. Follow one element. At each recursion level its subarray shrinks by a factor \(\le3/4\) with probability \(\ge1/2\) (the pivot lands in the middle half). After \(\log_{4/3}n\) such "good" levels the subarray has size 1. A Chernoff bound shows that more than \(8\log_{4/3}n\) levels occur with probability \(\le n^{-2}\). A union bound over \(n\) elements gives a recursion depth of \(O(\log n)\) with probability \(\ge1-1/n\). Each level costs \(\le n\).

Spread: the standard deviation of \(X\) is \(\sim0.65\,n\) (Knuth), while the mean is \(\sim2n\ln n\). Relative spread → 0 as \(n\) grows.
Why engineers careLatency SLOs are about tails (p99), not means. A guarantee "with probability \(1-n^{-c}\)" says something about the tail. An expectation alone says nothing.

Randomized quickselect: expected \(\le 4n\) comparisons

Selecting rank \(k\). Pair \(z_i,z_j\) (\(i<j\)) is compared iff the first pivot chosen from \(\{z_{\min(i,k)},\dots,z_{\max(j,k)}\}\) is \(z_i\) or \(z_j\):

\[\Pr[z_i,z_j\text{ compared}]=\frac{2}{\max(j,k)-\min(i,k)+1}.\]

Split the pairs into three groups:

  • \(i<j\le k\): probability \(\frac{2}{k-i+1}\), and \(k-i\) such \(j\) per \(i\) → total \(\le2k\).
  • \(k\le i<j\): symmetric → total \(\le2(n-k+1)\).
  • \(i<k<j\): for span \(d=j-i+1\) there are \(\le d-2\) such pairs → \(\sum_d\frac{2(d-2)}{d}\le2n\).
\(\mathbb E[\text{comparisons}]\le4n+O(1)\): linear in expectation.
Exact for the median: \(2(1+\ln2)\,n\approx\mathbf{3.386\,n}\). Measured in L02: 3.4n.

Implementation: getting the randomness right

Legacy code (two bugs)

int randomizedPartition(int A[], int low, int high) {
    srand(time(NULL));                          // BUG 1
    int randomIndex = low + rand() % (high - low); // BUG 2
    swap(A[randomIndex], A[high]);
    return partition(A, low, high);
}

Correct

static std::mt19937_64 rng(seed);  // seeded ONCE; seed logged
size_t pick(size_t lo, size_t hi) {
    std::uniform_int_distribution<size_t> d(lo, hi); // inclusive
    return d(rng);
}

Block C · 02:10–02:55

Choosing probabilistic guarantees

Questions to ask · an experiment · design exercise

Five questions before trusting a randomized algorithm

  1. What can go wrong: time or answer? (LV vs. MC.) Which failure is acceptable in this application?
  2. Over what is the probability taken? Our coins only? Or also an assumption about inputs?
  3. Who is the adversary? Oblivious (the guarantee holds) or adaptive / able to predict our randomness (it may not)?
  4. Can answers be verified? If so, MC can become LV, and errors can be caught downstream.
  5. What does amplification cost? Repetitions to reach the target \(\delta\), and are the repetitions really independent?
And an engineering sixth: reproducibility. Log seeds; make experiments rerunnable; separate "secret seed in production" from "fixed seed in testing".

Exercise C: design with randomness

  1. Budget. For \(n=10^4\), how many Freivalds trials give error \(\le10^{-12}\)? Compare the cost in scalar multiplications with recomputing \(AB\).
  2. LV → MC. Randomized quickselect uses \(\le4n\) comparisons in expectation. Give a Monte Carlo version that always stops within \(40n\) comparisons, and bound its failure probability. Can you make the failure probability \(2^{-10}\) within \(100n\)?

Groups · 15 min

Synthesis

  1. Las Vegas (always correct, random time) vs. Monte Carlo (bounded time, error \(\le\delta\), one- or two-sided).
  2. Expected time = \(\max_x\mathbb E_r[T(x,r)]\): worst-case input, our coins. Valid against oblivious adversaries only.
  3. Indicators + linearity: decompose a complicated cost into 0/1 events and add their probabilities. Quicksort: \(2(n+1)H_n-4n\); quickselect: \(\le4n\).
  4. Deferred decisions and amplification: error \(2^{-k}\) costs \(k\) independent runs.
  5. Tails matter: high-probability bounds, not just expectations.
