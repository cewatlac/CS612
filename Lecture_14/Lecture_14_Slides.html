Approximation guarantees

Ratios · vertex cover · set cover · limits

Approximation ratio; guarantee vs. heuristic

DefinitionA polynomial-time algorithm \(A\) is a \(\rho\)-approximation (\(\rho\ge1\)) if for every instance \(I\):
  • minimisation: \(A(I)\le\rho\cdot\mathrm{OPT}(I)\);
  • maximisation: \(A(I)\ge\mathrm{OPT}(I)/\rho\).

The proof pattern: find a quantity \(L(I)\) that the algorithm can compute with \(L(I)\le\mathrm{OPT}(I)\) (a lower bound), and show \(A(I)\le\rho\,L(I)\).

Approximation algorithmHeuristic
Qualityproved for every inputmeasured on some inputs
Typical resultoften much better than \(\rho\)often excellent
Adversarial inputsstill within \(\rho\)can be arbitrarily bad
Evidencea theoremexperiments (and their threats to validity)

Vertex cover: two 2-approximations

1 · Maximal matching

Repeatedly take an uncovered edge and add both endpoints.

Lower bound: the chosen edges form a matching \(M\); any cover needs a distinct endpoint of each, so \(\mathrm{OPT}\ge|M|\). The output has \(2|M|\le2\,\mathrm{OPT}\) vertices.

Tight: a perfect matching graph gives \(2n\) vs. \(n\).

2 · LP rounding (weighted)

Solve the LP relaxation: minimise \(\sum w_vx_v\) subject to \(x_u+x_v\ge1\) for every edge and \(0\le x\le1\). Output \(C=\{v: x_v\ge\frac12\}\).

  • A cover: each edge has an endpoint with \(x\ge\frac12\).
  • \(w(C)\le\sum_{v\in C}w_v\cdot2x_v\le2\,\mathrm{LP}\le2\,\mathrm{OPT}\) (the LP is a relaxation, so \(\mathrm{LP}\le\mathrm{OPT}\)).
Better than 2? Not known. It is NP-hard to do better than \(\sqrt2\approx1.414\) (Khot–Minzer–Safra 2017), and under the Unique Games Conjecture, factor \(2-\varepsilon\) is impossible.

Greedy set cover: an \(H_n\)-approximation

Universe \(U\) (\(|U|=n\)), sets \(S_1..S_t\). Greedy: repeatedly pick the set covering the most uncovered elements.

TheoremGreedy uses \(\le H_n\cdot\mathrm{OPT}\) sets, where \(H_n=\sum_{i=1}^n\frac1i\le\ln n+1\).
Proof (pricing)When greedy picks a set covering \(c\) new elements, charge each of them \(\frac1c\). The total charge = the number of greedy sets. Fix an optimal set \(S^\ast\) and list its elements in the order greedy covers them: \(e_1,\dots,e_d\). When \(e_j\) is covered, at least \(d-j+1\) elements of \(S^\ast\) are still uncovered, so greedy's choice covers \(\ge d-j+1\) new elements and \(e_j\) pays \(\le\frac{1}{d-j+1}\). So \(S^\ast\)'s elements pay \(\le H_d\le H_n\). Summing over the OPT sets, which cover everything, gives greedy \(\le H_n\cdot\mathrm{OPT}\).
Can we do better?No, essentially: approximating set cover within \((1-\varepsilon)\ln n\) is NP-hard (Feige 1998; Dinur–Steurer 2014). Greedy is essentially optimal among polynomial algorithms.
TightnessThere are instances where greedy is \(\Theta(\log n)\) times optimal: two disjoint "row" sets cover everything, while greedy picks a sequence of "column" sets of sizes \(2^{k-1},\dots,2,1\).

TSP, schemes, and heuristics

Metric TSP · impossibility · FPTAS · local search

Metric TSP: the double-tree 2-approximation

Metric: \(d(u,w)\le d(u,v)+d(v,w)\) (the triangle inequality).

  1. Compute an MST \(T\) (L09).
  2. Walk around \(T\) (a DFS preorder), visiting each vertex the first time it is seen, i.e. shortcut repeated vertices.
Proof
  • Lower bound: removing one edge from an optimal tour gives a spanning tree, so \(w(T)\le\mathrm{OPT}\).
  • The full walk traverses each tree edge twice: cost \(2w(T)\).
  • Shortcutting never increases the cost (triangle inequality).
  • So the tour costs \(\le2w(T)\le2\,\mathrm{OPT}\).
Christofides (1976)MST + a minimum-weight perfect matching on the odd-degree vertices + an Euler tour + shortcuts: a 1.5-approximation. (Recently improved to \(1.5-10^{-36}\): Karlin, Klein, Oveis Gharan 2021.)
No triangle inequality: no approximationFor every constant \(\rho\), a \(\rho\)-approximation for general TSP would decide Hamiltonian cycle (L13 exercise B2: weight 1 on edges, \(\rho n+1\) on non-edges). So none exists unless P = NP.

Approximation schemes: the knapsack FPTAS

Recall L07: the value-indexed DP runs in \(O(n\cdot\sum v_i)\). Values are the problem, so scale them down.

  1. Let \(v_{\max}\) be the largest value (items heavier than \(W\) removed), and \(K=\varepsilon v_{\max}/n\).
  2. Rounded values \(v'_i=\lfloor v_i/K\rfloor\) (at most \(n/\varepsilon\)).
  3. Solve exactly with the value DP on \(v'\): \(O(n\cdot n\cdot n/\varepsilon)=O(n^3/\varepsilon)\).
GuaranteeRounding loses \(<K\) per item, so \(<nK=\varepsilon v_{\max}\le\varepsilon\,\mathrm{OPT}\) in total. The solution found has value \(\ge(1-\varepsilon)\mathrm{OPT}\).
Why this is possible for knapsack but not for TSP

Knapsack is only weakly NP-hard: its hardness lives in the large numbers, and rounding removes them at a controlled cost.

Strongly NP-hard problems have no FPTAS (unless P = NP). The L07/L13 distinction pays off here.

Heuristics and local search

  • Constructive heuristics: nearest neighbour (TSP), greedy by density (knapsack), and so on. Fast, and no (constant) guarantee.
  • Local search: start from a solution; apply improving moves until none exists (a local optimum). TSP 2-opt: replace edges \((a,b),(c,d)\) by \((a,c),(b,d)\) if that is shorter.
  • Metaheuristics: simulated annealing, tabu search, genetic algorithms. Escape local optima; tuned empirically.
  • Randomisation: random restarts, randomized rounding of LPs (which sometimes does give guarantees).
What local search guarantees

Only local optimality with respect to the moves. 2-opt on metric TSP has worst-case ratio \(\Theta(\log n/\log\log n)\), and it can take exponentially many steps in the worst case.

Yet on real and random instances 2-opt is often within a few percent of optimal. That is an empirical fact to be measured, with the input family stated.

Course synthesis: facing a new computational problem

  1. Model: input, output, input size (bits!), cost model. What is fixed, and what varies (L01, L07)?
  2. Assumptions: weights, adversary, distributions, static vs. dynamic, sparse vs. dense, metric, small parameters (L04, L10).
  3. Paradigm: D&C (L02), randomization (L03), augmentation / amortization (L05), DP state design (L06–L07), greedy/matroid (L08), graphs and flow (L09–L12), strings (L11).
  4. Correctness: invariants, induction, exchange, cut/cycle, reductions (L01, L08, L13).
  5. Complexity: worst/expected/amortized/w.h.p./approximate, and the lower bound (L01–L05, L09).
  6. Hardness: is an exact efficient algorithm plausible? Weak or strong (L07, L13)?
  7. Alternatives: when does each one win?
  8. Evidence: hypotheses first; controlled inputs that stress the assumptions; spread; threats to validity (the project).
The recurring lesson

A result is a claim + its guarantee type + its assumptions + its evidence.

"Dijkstra is \(O(m\log n)\)" is incomplete. "Dijkstra with a binary heap is \(O((n+m)\log n)\) worst case for non-negative weights, and on sparse random graphs it beat Bellman–Ford only by a constant, because of early termination" is an MSc answer.
