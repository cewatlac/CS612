What exactly are we claiming?

Models · input size · kinds of guarantee · bounds · asymptotics vs. practice

Four different guarantees (do not mix them up)

\(T(x)\) = cost on input \(x\); \(T(x,r)\) = cost on input \(x\) with random bits \(r\).

GuaranteeDefinitionRandomness over…
Worst case\(\displaystyle T_{\text{wc}}(n)=\max_{|x|=n} T(x)\)none
Average case\(\displaystyle T_{\text{avg}}(n)=\mathbb{E}_{x\sim\mathcal D_n}[T(x)]\)the input (assumed distribution \(\mathcal D_n\))
Expected (randomized alg.)\(\displaystyle T_{\text{exp}}(n)=\max_{|x|=n}\ \mathbb{E}_{r}[T(x,r)]\)the algorithm's own coins; input is worst case
Amortized\(\displaystyle \max_{\text{sequences } \sigma \text{ of } m \text{ ops}} \tfrac{1}{m}\sum_{i} c_i\)none: worst case over sequences
Average case trusts the input distribution. Expected time trusts only your own random number generator. Amortized involves no probability at all.

Asymptotic notation, formally

For \(f,g:\mathbb N\to\mathbb R_{\ge 0}\):

\(f=O(g)\)\(\exists\, c>0,\ n_0:\ \ f(n)\le c\,g(n)\ \text{ for all } n\ge n_0\)upper bound
\(f=\Omega(g)\)\(\exists\, c>0,\ n_0:\ \ f(n)\ge c\,g(n)\ \text{ for all } n\ge n_0\)lower bound
\(f=\Theta(g)\)\(f=O(g)\) and \(f=\Omega(g)\)tight bound
\(f=o(g)\)\(\forall\, c>0\ \exists\, n_0:\ \ f(n)< c\,g(n)\ \text{ for all } n\ge n_0\)strictly smaller order
\(f=\omega(g)\)\(g=o(f)\)strictly larger order
These are statements about functions

\(O\), \(\Omega\), \(\Theta\) compare two functions. They are not "cases".

"Worst case" and "best case" choose which function we are describing.

Each combination is meaningful: the worst case can have an \(\Omega\) bound and the best case can have an \(O\) bound.

Algorithm bounds vs. problem bounds

About an algorithm \(A\)

  • Upper bound: \(T_A(n) = O(g)\), i.e. \(A\) never costs more than this
  • Lower bound: \(T_A(n) = \Omega(g)\), i.e. \(A\) really does cost this on some inputs (worst case)
  • Proved by analysing this one algorithm

About a problem \(P\) (in a model)

  • Upper bound: some algorithm solves \(P\) in \(O(g)\)
  • Lower bound: every algorithm for \(P\) in the model needs \(\Omega(g)\)
  • Tight when they match. Example: comparison sorting is \(\Theta(n\log n)\).
Why this matters

An upper bound is an algorithm. A lower bound is a theorem about all algorithms, including ones nobody has invented yet.

Once they match, you stop searching for a faster algorithm in that model. To go faster you have to change the model or the assumptions.

Asymptotics vs. practice

  • Constants and lower-order terms: insertion sort beats merge sort below roughly 16–64 elements, so library sorts switch to it for small subarrays.
  • Memory hierarchy: a cache miss costs about 100 comparisons. Cache-friendly \(\Theta(n\log n)\) code can beat pointer-chasing \(\Theta(n)\) code.
  • Input distributions: real data is often nearly sorted, skewed or adversarial.
  • Galactic algorithms: asymptotically best, never practical (e.g. fast matrix multiplication with \(\omega<2.372\)).
  • Which cost? Comparisons, time, memory, I/Os, energy. These can disagree.
Look ahead (Block C data) std::sort makes ~30–40% more comparisons than merge sort on random input, yet it is the default in practice. Why might that be sensible?

Block B · 01:10–02:00

Proving algorithms correct

Invariants · induction · contradiction · counterexamples · exchange arguments (preview)

What a correctness proof must establish

  1. Specification: precondition (valid inputs) and postcondition (required output). Without a spec there is nothing to prove.
  2. Partial correctness: if the algorithm terminates on a valid input, the output satisfies the postcondition.
  3. Termination: it does terminate, usually via a variant, a non-negative integer that strictly decreases on every iteration or recursive call.

Total correctness = 2 + 3.

Toolbox
Loopsloop invariant + variant
Recursion(strong) induction on input size
Optimalitycontradiction; exchange / cut arguments
Refutationcounterexample
Testing can show the presence of bugs, never their absence. A proof covers all inputs that satisfy the precondition.

Loop invariants: binary search done right

Spec. Pre: \(A[0..n-1]\) sorted non-decreasingly. Post: return the smallest \(i\in[0,n]\) with \(A[i]\ge x\) (or \(n\) if none).

Invariant \(I\): \(0\le lo\le hi\le n\), \(A[j]<x\) for all \(j<lo\), and \(A[j]\ge x\) for all \(j\ge hi\).

Variant: \(hi-lo\).

LOWER-BOUND(A, n, x)
  lo = 0 ; hi = n
  while lo < hi
      mid = lo + ⌊(hi − lo) / 2⌋
      if A[mid] < x
          lo = mid + 1
      else
          hi = mid
  return lo
Initialization. \(lo=0,hi=n\): both "for all" ranges are empty, so \(I\) holds.
Maintenance. \(lo\le mid<hi\). If \(A[mid]<x\), sortedness gives \(A[j]<x\) for all \(j\le mid\), so \(lo=mid+1\) preserves \(I\). Otherwise \(A[j]\ge x\) for all \(j\ge mid\), so \(hi=mid\) does.
Termination. \(hi-lo\) strictly decreases, because \(mid<hi\) and \(mid+1>lo\). At exit \(lo=hi\); by \(I\), \(lo\) is the smallest index with \(A[lo]\ge x\).

Induction for recursive algorithms

POWER(a, n)          ▷ n ≥ 0 integer
  if n == 0
      return 1
  h = POWER(a, ⌊n/2⌋)
  if n is even
      return h · h
  else
      return h · h · a

Claim. For all \(n\ge 0\): \(\text{POWER}(a,n)=a^n\).

Proof (strong induction on \(n\)). Base \(n=0\): returns \(1=a^0\). Step: for \(n\ge1\), \(\lfloor n/2\rfloor<n\), so by hypothesis \(h=a^{\lfloor n/2\rfloor}\). If \(n=2k\): \(h^2=a^{2k}\). If \(n=2k+1\): \(h^2a=a^{2k+1}\).

Termination is part of the same induction: every call is on a strictly smaller non-negative integer.

Cost. \(T(n)=T(\lfloor n/2\rfloor)+O(1)\Rightarrow O(\log n)\) multiplications. How many bit operations?

Contradiction: finding the maximum needs \(n-1\) comparisons

Claim. Every comparison-based algorithm that always returns the maximum of \(n\) distinct keys makes at least \(n-1\) comparisons in the worst case.

Proof. Call a key a loser once it has been smaller in some comparison. Suppose the algorithm stops after fewer than \(n-1\) comparisons. Each comparison creates at most one new loser, so at least two keys, \(u\) and \(v\), have never lost. The algorithm outputs one of them, say \(u\). Now change the input by raising \(v\) above every other key. Every comparison involving \(v\) had \(v\) as the winner, so all comparison outcomes are unchanged, the algorithm behaves identically, and it outputs \(u\), which is wrong. Contradiction. \(\blacksquare\)

Pattern

Assume a better algorithm exists → build an input on which it is fooled.

This is an adversary argument. The same idea proves lower bounds in Block C.

Counterexamples: the fastest way to kill a claim

Claim A: greedy coin change is optimal

Coins \(\{1,3,4\}\), amount \(6\). Greedy: \(4+1+1\) = 3 coins. Optimal: \(3+3\) = 2 coins. ✗

Greedy is optimal for some coin systems (e.g. \(\{1,5,10,25\}\)). Knowing when is L08 material.

Claim B: shortest-first maximises the number of non-overlapping intervals

\([0,5),[4,7),[6,11)\): shortest-first picks \([4,7)\) only. Optimal: \([0,5),[6,11)\). ✗

How to find counterexamples systematically
  1. Try tiny inputs (\(n\le 4\)) and extreme structure: all equal, sorted, reversed, one huge value.
  2. Identify the "decision" the rule makes and construct an input where that decision blocks a better one.
  3. Mechanise: brute force vs. candidate on thousands of random small inputs (differential testing).

Preview: exchange arguments

Rule: repeatedly pick the compatible interval that finishes earliest.

Exchange lemma. Let \(g\) be the interval with the earliest finish time. Some optimal solution contains \(g\).

Proof. Take any optimal solution \(O\), sorted by finish time, with first interval \(o_1\). Since \(f(g)\le f(o_1)\), replacing \(o_1\) by \(g\) conflicts with nothing: every other interval in \(O\) starts after \(f(o_1)\ge f(g)\). The new solution is feasible and has \(|O|\) intervals, so it is optimal. Then apply induction to the intervals that start after \(f(g)\).

Template (L08, L09)
  1. Take an arbitrary optimal solution \(O\).
  2. If it differs from greedy, exchange one piece towards greedy's choice.
  3. Show the result is still feasible and no worse.
  4. Repeat or induct: greedy's solution is optimal.

Cut property for MSTs (L09) is the same argument.

Exercise B: find the flaw

Spec. \(A\) sorted, \(A[0]\le x\). Return the largest \(i\) with \(A[i]\le x\).

LAST-LE(A, n, x)
  lo = 0 ; hi = n − 1
  while lo < hi
      mid = ⌊(lo + hi) / 2⌋
      if A[mid] ≤ x
          lo = mid
      else
          hi = mid − 1
  return lo
A student's "proof" Invariant: \(A[lo]\le x\), and every \(j>hi\) has \(A[j]>x\). Both branches preserve it. The interval \([lo,hi]\) shrinks every iteration, so the loop terminates, and at exit \(lo=hi\) is the answer.

Block C · 02:10–02:55

Lower bounds: proving that nothing is faster

Decision trees · \(\Omega(n\log n)\) · what the bound does not say · experiment

The comparison decision tree

  • Fix \(n\). Any deterministic comparison sort, run on inputs of size \(n\), is a binary tree: internal node = a comparison \(a_i \le a_j\)?; leaf = an output permutation.
  • One execution = one root-to-leaf path. Worst-case comparisons = height.
  • Correctness forces every one of the \(n!\) orderings to reach a leaf labelled with the right permutation, so there are \(\ge n!\) leaves.

Theorem: comparison sorting needs \(\Omega(n\log n)\)

TheoremEvery comparison sort makes at least \(\lceil \log_2 n!\rceil = n\log_2 n - n\log_2 e + O(\log n)\) comparisons in the worst case, and at least \(\log_2 n!\) on average over a uniformly random permutation.
Proof A binary tree of height \(h\) has at most \(2^h\) leaves. We need \(2^h \ge n!\), so \(h\ge\log_2 n!\). And \[\log_2 n! = \sum_{i=1}^{n}\log_2 i \;\ge\; \sum_{i=\lceil n/2\rceil}^{n}\log_2 i \;\ge\; \frac n2\log_2\frac n2 \;=\; \Omega(n\log n).\] Average case: among binary trees with \(L\) leaves, average leaf depth \(\ge\log_2 L\) (proof by induction or by convexity; balanced trees are best).

Vendor claim 1: \(\lceil\log_2 20!\rceil = 62 > 60 = 3\cdot 20\), so "\(3n\) comparisons on any input" is impossible for every \(n\ge 20\). For \(n=10^6\): \(\log_2 n! \approx 1.85\times 10^7 \gg 3\times10^6\).

What the lower bound does not say

Counting sort: keys in \([0,K)\)

Count occurrences, take prefix sums, place each key. \(\Theta(n+K)\) time and space. It never compares two keys: it uses a key as an array index.

Radix sort: \(b\)-bit keys, digits of \(r\) bits

\(\lceil b/r\rceil\) stable counting-sort passes: \(\Theta\big(\tfrac{b}{r}(n+2^r)\big)\). With \(r\approx\log_2 n\): \(\Theta\big(\tfrac{b\,n}{\log n}\big)\), i.e. \(\Theta(n)\) when \(b=O(\log n)\).

No contradiction The theorem is about the comparison model. Counting and radix sort run in the word-RAM and assume integer keys from a bounded universe.
The price of the assumption Counting sort pays \(\Theta(K)\) memory and time. Radix sort's cost depends on the key length \(b\). For arbitrary comparable objects (strings, tuples with a custom order), you are back in the comparison model.

Synthesis: what to carry forward

  1. A complexity claim = model + input size + cost measure + kind of guarantee + bound.
  2. \(O/\Omega/\Theta\) compare functions. Worst/best/average/expected/amortized choose the function. Keep the two axes separate.
  3. Correctness = specification + partial correctness + termination. Invariants for loops, induction for recursion, exchange arguments for greedy.
  4. A problem lower bound is a theorem about all algorithms in a model: adversaries, decision trees, reductions.
  5. Beating a lower bound always means changing the model or adding an assumption, and assumptions have costs you can measure.
