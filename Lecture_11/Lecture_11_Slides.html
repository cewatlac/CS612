Motivating problem

A security team scans \(10^9\) characters of logs per day for any of \(5{,}000\) indicator strings (lengths 6–40).

  • One pattern at a time with a good single-pattern algorithm: \(5000\) passes over \(10^9\) characters.
  • Compare hashes of windows with a hash set of pattern hashes? Fast, but what if two different strings have equal hashes?
Equal hashes ≠ equal strings

By pigeonhole, a hash with \(p\) values has collisions among \(p+1\) strings. Collisions are not only theoretical:

  • Two different PDF files with the same SHA-1 hash were published in 2017 (the "SHAttered" attack).
  • Polynomial hashes modulo \(2^{64}\) with a fixed base are broken by Thue–Morse strings, a well-known competitive-programming trap.

One pattern

Baseline · rolling hashes · Rabin–Karp · KMP

The baseline: naive matching

Try every shift \(s=0..n-m\) and compare characters until the first mismatch.

  • Worst case \(\Theta(nm)\): text \(a^n\), pattern \(a^{m-1}b\). Every shift compares \(m\) characters.
  • Random text over an alphabet of size \(\sigma\): the expected comparisons per shift are \(\le\frac{1}{1-1/\sigma}\le2\). Expected \(O(n)\) for any fixed pattern.
  • It needs no preprocessing, no memory, and has a tight inner loop. Real libraries often use naive search or variants with skips (Boyer–Moore–Horspool).
Why a "bad" algorithm is a good baselineIt is correct by inspection, so it is the oracle for differential testing, and on natural text it is hard to beat. The value of the others lies in their guarantees: worst-case linear (KMP), and the ability to compare many things at once (hashing, automata).

Polynomial rolling hashes

For a window \(x=x_0x_1\cdots x_{m-1}\) (characters as integers \(<p\)), a prime \(p\) and a base \(b\in\{0,\dots,p-1\}\):

\[h_b(x)=\Big(\sum_{i=0}^{m-1}x_i\,b^{m-1-i}\Big)\bmod p .\]

Rolling: sliding the window from \(T[s..s+m-1]\) to \(T[s+1..s+m]\):

\[h\leftarrow\big((h-T[s]\,b^{m-1})\cdot b+T[s+m]\big)\bmod p\qquad O(1)\text{ per shift.}\]
Collision bound (idea)Fix \(x\ne y\) of length \(m\) before choosing \(b\) uniformly at random. Then \(h_b(x)-h_b(y)\) is a nonzero polynomial in \(b\) of degree \(\le m-1\) over the field \(\mathbb Z_p\), so it has at most \(m-1\) roots: \(\Pr_b[\text{collision}]\le\frac{m-1}{p}\).
Conditions that matter
  • \(b\) must be random and chosen after the strings are fixed (an oblivious adversary).
  • \(p\) must be prime (a field). Working modulo \(2^{64}\) is not a field.
  • The bound is per comparison: use a union bound over all windows.

Rabin–Karp: Monte Carlo or Las Vegas

RABIN-KARP(T, P)
  choose b uniformly at random     ▷ after T and P are fixed
  hp = h(P) ; ht = h(T[0..m−1])
  for s = 0 to n − m
      if ht == hp
          if T[s..s+m−1] == P        ▷ verification
              report s
      roll ht to the next window

KMP: the prefix function

A border of a string is a proper prefix that is also a suffix.

\(\pi[i]\) = the length of the longest border of \(P[0..i]\).

\(i\)0123456
\(P\)aabaaab
\(\pi\)0101223

Key fact: the borders of \(P[0..i]\) are exactly \(\pi[i],\ \pi[\pi[i]-1],\dots\) (the border chain).

KMP-MATCH(T, P, π)
  q = 0                       ▷ length of the current match
  for each character c of T
      while q > 0 and P[q] ≠ c
          q = π[q − 1]        ▷ fall back to the next border
      if P[q] == c: q = q + 1
      if q == m
          report a match ; q = π[m − 1]
InvariantAfter reading \(T[0..i]\), \(q\) = the length of the longest prefix of \(P\) that is a suffix of \(T[0..i]\).

KMP matching is linear: a potential argument

ClaimKMP-MATCH makes \(O(n)\) character comparisons on a text of length \(n\), whatever the text.
ProofLet \(\Phi=q\ge0\), with \(\Phi=0\) initially. Each text character increases \(q\) by at most 1 (the single q = q + 1). Each iteration of the while-loop decreases \(q\) strictly (\(\pi[q-1]<q\)), and so does the reset after a match. The total decrease cannot exceed the total increase, which is \(\le n\). So there are \(\le n\) while-iterations in total, and the total work is \(O(n)\). (Amortized: \(\le2\) comparisons per text character.)
Deterministic guarantee\(O(n+m)\) worst case for every input: no probability, no adversary model. It is a streaming algorithm (reads each character once) with \(O(m)\) memory.
Computing \(\pi\) itself in \(O(m)\) uses the same kind of argument with a different potential. (Proof: PS4.)

Tries: the starting point

  • A rooted tree whose edges are labelled with characters. Each pattern is a root-to-node path, and terminal nodes are marked.
  • Insert/search a string of length \(\ell\): \(O(\ell)\) steps, independent of the number of stored strings.
  • Size: at most \(M+1\) nodes for patterns of total length \(M\), with shared prefixes stored once.

AskTo find occurrences of any of \(k\) patterns in a text, walk the trie from every text position. What does that cost? What is wasted when a walk fails?

Aho–Corasick (1975): KMP on a trie

  • Failure link \(f(v)\): the node for the longest proper suffix of \(v\)'s string that is also in the trie. (For one pattern, this is exactly \(\pi\).)
  • Output (dictionary) link: the nearest node on the failure chain that ends a pattern. It reports every pattern that ends here.
  • Matching: read the text; follow a trie edge if one exists, otherwise follow failure links. Report outputs at each position.

Example patterns: he, she, his, hers.

Aho–Corasick: construction, correctness, cost

BUILD-FAILURE(trie)
  f(root) = root ; children of root: f = root
  BFS over nodes v (by depth)
      for each child u = child(v, c)
          x = f(v)
          while x ≠ root and child(x, c) undefined
              x = f(x)
          f(u) = child(x, c) if defined (and ≠ u) else root
          out(u) = f(u) if f(u) ends a pattern else out(f(u))

Why BFS: \(f(u)\) is shorter than \(u\), so it is already final when \(u\) is processed.

Invariant (matching)After reading \(T[0..i]\), the current node is the longest suffix of \(T[0..i]\) that is a trie node. Every pattern ending at \(i\) is a suffix of it, and all of them lie on its output chain.
ComplexityBuild \(O(M\sigma)\) with a full goto table (\(O(M)\) with maps); match \(O(n+\text{occ})\) with output links. Independent of \(k\), apart from \(M\).
\(\text{occ}\) can be huge: patterns \(a,aa,\dots,a^k\) in text \(a^n\) give \(\Theta(nk)\) matches. Output-sensitive, not linear.

Optional: indexing the text instead (suffix arrays)

When the text is fixed and patterns arrive later (a search index), preprocess the text instead of the patterns.

  • Suffix array SA: the starting positions of all suffixes, in sorted order. Build in \(O(n\log n)\) (prefix doubling) or \(O(n)\) (SA-IS).
  • Search for \(P\): binary search over SA: \(O(m\log n)\) (\(O(m+\log n)\) with LCP information).
  • LCP array: the longest common prefix of adjacent sorted suffixes, in \(O(n)\) (Kasai).
  • Example: the longest repeated substring = the maximum of LCP.

Synthesis

  1. Naive is the correct baseline and oracle: expected fast on natural text, \(\Theta(nm)\) in the worst case.
  2. Polynomial hashing with a random base modulo a prime: collision \(\le(m-1)/p\) per comparison; union bound over windows. Equal hashes never prove equal strings. Verify for Las Vegas.
  3. KMP: the border chain + the invariant; linear by a potential argument; deterministic and streaming.
  4. Aho–Corasick: KMP on a trie; \(O(n+M+\text{occ})\), independent of \(k\). Mind \(\text{occ}\) and memory.
  5. Choose by what is fixed: the pattern (KMP), a pattern set (AC), or the text (suffix arrays).
